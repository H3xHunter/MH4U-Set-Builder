# Data format (`public/data/*.json`)

Generated by `python3 -I tools/convert.py --db PATH --out public/data --source-url URL --source-commit HASH` from the
MH4U Database SQLite file (see `_inspect/REPORT.md` for source notes). Never edit these files by hand.

General rules
- JSON, UTF-8, compact, keys sorted, one trailing newline. Same input gives byte-identical output.
- Lists are sorted by `id` (database `_id`, preserved as-is). Ids are the database's integer ids, never array indexes.
- Blank strings (`''`) become `null`. Names are English only, exactly as stored (abbreviations such as "Jwl" are kept).
- Object keys that are skill tree ids (`skills`) are strings, because JSON keys must be strings.
- The converter exits non-zero if a referenced id is missing, an id is duplicated within a file, or a skill tree has
  two tiers with the same points.
- "Meaning unverified" below means the value is passed through from the source and the owner has not confirmed
  what it means in the game.

## meta.json
`dataVersion` (int, 1), `sourceUrl`, `sourceCommit`, `dbSha256` (SHA-256 of the input DB file), `license`
(MIT notice text; applies to the app source, game data is Capcom's), `torsoUpTreeId` (original id of the skill tree
named "Torso Up"), `counts` (records per file: armor, decorations, horn, locations, materials, monsters, skills,
weapons, quests, items). No timestamp.

## skills.json
`[{id, name, tiers:[{points, name, description}]}]`. Tiers ascending by `points` (negative values allowed; they come
from `skills.required_skill_tree_points`). `description` is English text or null. The "Torso Up" tree is **excluded**
(it must exist exactly once in the source, otherwise conversion fails).

## armor.json
`[{id, name, slot, hunterType, gender, slots, defense, maxDefense, res, skills, torsoUp, rarity, materials}]`
- `slot`: `head | chest | arms | waist | legs` (source "Body" is `chest`).
- `hunterType`: `blade | gunner | both | null`. `gender`: `male | female | both | null`.
  Null means the source was blank (one piece: Hawkeye Earring, id 3753; a warning is logged).
- `slots`: decoration capacity 0-3. `defense`: integer, as stored. `maxDefense`: number | null (null on 41 armor pieces; meaning unknown, do not infer).
- `res`: `{fire, water, thunder, ice, dragon}` integers.
- `skills`: `{treeId: points}`, non-zero only, negatives kept, Torso Up never listed.
- `torsoUp`: true if the source piece had the Torso Up tree.
- `rarity`: as stored in items.
- `materials`: `[{itemId, quantity, kind}]`, `kind` is `create | createA | createB | improve` (from `components.type`; the
  meaning of A/B is unverified). Only `create` appears in the current data; the other values are allowed. Order follows the source row order. Item ids refer to `materials.json`.
- There is **no rank (LR/HR/G) on armor**; the source does not store it.

## decorations.json
`[{id, name, size, skills, color}]`. `size` = slots used. `skills` as in armor (negatives kept).
`color`: `blue | cyan | green | grey | orange | pink | purple | red | white | yellow | unknown`, taken from the source
`items.icon_name` (`Jewel-<Color>.png`, lowercased; the filename itself is not stored). The color is the jewel's icon
color in the source. It follows the skill tree, not the size or rarity (checked: no skill tree with positive points
has two colors), so the UI can use it to pick a jewel icon. `unknown` is the source's own "Jewel-Unknown" value (2
decorations). The converter fails if `icon_name` does not match the pattern or the color is not in this set.

## weapons.json
`[{id, name, class, parentId, final, rarity, attack, maxAttack, affinity, affinityOptions, element, element2,
awaken, defenseBonus, sharpness, slots, hornNotes, creationCost, upgradeCost, materials, requiresWeapon, extra}]`
- `class`: source sub_type (e.g. "Great Sword", "Sword and Shield", "Light Bowgun").
- `parentId`: previous weapon in the upgrade tree, or null (the source uses 0 for "none"; ids start at 1).
- `final`: boolean. `attack`: integer. `maxAttack`: number | null (null for all weapons in the current data). Both as stored; whether they equal in-game displayed attack is unverified.
- `affinity`: integer, or null when `affinityOptions` is set. Plain integer text -> that integer. Blank in the source is
  treated as 0 (owner-confirmed rule). Any other text makes the conversion fail.
- `affinityOptions`: null, or `[a, b]` (in source order) when the source text is two integers such as "-45/20". The
  weapon randomly applies one of these values (Chaotic Gore Magala weapons, quests, items). The probability and the trigger are
  unknown; consumers must not average them without a documented rule. Text that is not exactly two integers fails the
  conversion.
- `element`, `element2`, `awaken`: `{type, value}` or null; `type` is the source text (e.g. "Fire", "Poison", "Blastblight").
  The source keeps some elements in `awaken` (awakened element); how it combines with `element` is unverified.
- `defenseBonus`: source `weapons.defense` as an integer (0 when none).
- `sharpness`: `{base:[7 ints], plus:[7 ints]}` or null. Order: red, orange, yellow, green, blue, white, purple.
  `plus` is the Sharpness+1 bar. Null for bows/bowguns (blank) and when the text does not match the expected
  format (warning; currently weapon 7324 "Emperor's Speech", whose second group has 8 values). The unit of the
  segments is unverified.
- `slots`: decoration capacity. `hornNotes`: note string like "PBR", else null.
- `creationCost`, `upgradeCost`: zenny to forge the weapon from scratch, and to upgrade it from its parent. Integer or
  null. Null when the source column is blank or NULL (1696 and 412 weapons), never 0 as a stand-in. A stored 0 is kept
  as 0 (15 weapons have `creationCost` 0: Rusted/Worn starter weapons, Demon's Isle, God's Isle; meaning unverified).
  Source text that is not an integer becomes null with a warning (weapon 6808 Demonlord Cudgel, `upgradeCost`, the
  source text means "variable materials"). A negative number fails the conversion.
- `materials`: `[{itemId, quantity, kind}]` like armor, with `kind` `create | improve` only (the source has no other
  kind for weapons; one would fail the conversion). `quantity` is a positive integer. `itemId` refers to
  `materials.json`. `create` is the cost to forge the weapon, `improve` the cost to upgrade it from its parent, so a
  weapon can have both (221 do). Lines are listed `create` first, then `improve`, each in source row order. A weapon
  with no recipe has `[]` (3 weapons: 5575, 5963, 5965).
  - **Parent ingredient rule.** In the source, the parent weapon appears as an ingredient (quantity 1) of the
    recipe. Weapon item ids are the weapon ids (checked for all 1916 such rows). That ingredient is **not** a
    material and is never listed in `materials`; the parent is `parentId`, and any weapon ingredient `parentId` does not
    cover is in `requiresWeapon`. The converter checks it: an `improve`
    recipe must have exactly one weapon ingredient and it must equal `parentId`. Where it does not, the converter
    prints a warning. In the current source this happens for 13
    weapons: 9 improve recipes with a `parentId` but no weapon ingredient (5026, 5121, 5465, 5566, 5954, 6171, 6349,
    6717, 6916) and 4 whose weapon ingredient is a different weapon (5257 needs 5267, 5694 needs 5692, 7098 needs 7095,
    7303 needs 7302 and has no parent). Whether those are real cross-tree requirements or source errors is unverified.
    A `create` recipe may also list the parent (21 weapons, all equal to `parentId`); it is dropped the same way.
  - Exact duplicate source rows (same weapon, item, kind, quantity) are kept once with a warning (weapons 5192, 5727,
    6165); the same item and kind with different quantities fails the conversion. Whether a duplicate row means
    "twice the quantity" is unverified.
- `requiresWeapon`: `{create, improve}`, every weapon has it. Each value is a weapon id or null. It is the weapon-type
  ingredient of that recipe kind, kept only when `parentId` does not already say it: always for `create`, and for
  `improve` only when the id differs from `parentId`. A normal improve step (ingredient equals `parentId`) is null.
  Current data: 21 `create` values (all equal `parentId`; none of these weapons is a root, and they have only create
  lines, so "create" there means forging directly from the parent) and 4 `improve` values (5257 needs 5267, 5694 needs
  5692, 7098 needs 7095, 7303 needs 7302 and has no `parentId`). The 9 improve recipes with a `parentId` but no
  weapon ingredient stay null on both. A recipe with more than one weapon ingredient is not guessed: it is null and
  the converter warns (none in the current data). The converter also warns about any cycle among `parentId` and
  `requiresWeapon` edges (none in the current data). A weapon that is its own parent, or requires itself, or requires
  an unknown weapon id, fails the conversion. The parent-ingredient warnings listed above are unchanged.
- `extra`: untouched text, null if blank: `shellingType, phial, charges, coatings, recoil, reloadSpeed, rapidFire,
  deviation, ammo, specialAmmo`. Not interpreted.

## horn.json
`[{notes, song, effect1, effect2, duration, extension}]`, source row order. A weapon's `hornNotes` matches `notes`
(matching rules unverified). No id (source `_id` is not exposed).

## materials.json
Only items used as armor or weapon recipe materials (every non-weapon item referenced by `armor[].materials` or
`weapons[].materials`). `[{id, name, rarity, drops, gathering, sources}]`
- `drops`: `[{monsterId, rank, condition, percentage, stackSize}]` from `hunting_rewards`; `rank` is `LR | HR | G`;
  `percentage` can be null (4 source rows are blank).
- `gathering`: `[{locationId, area, site, rank, quantity, percentage}]`.
- `sources`: all other places the source data links the item. Stored as-is, no game rules applied. Every key is
  always present; an empty array means "no link of that type". Order follows source row order.
  - `quests`: `[{questId, slot, percentage, stackSize}]` from `quest_rewards` (`slot` is `reward_slot`). `questId`
    refers to `quests.json` (kind `quest`). Quest rewards carry no LR/HR/G rank.
  - `arena`: `[{arenaQuestId, percentage, stackSize}]` from `arena_rewards`; refers to `quests.json` (kind `arena`).
  - `combining`: `[{item1Id, item2Id, amountMin, amountMax, percentage}]` where this material is the created item.
    Ingredient ids refer to `items.json` or `materials.json`.
  - `veggieElder`: `[{offerItemId, quantity}]` where this material is the received item (`receive_item_id`).
  - `wyporium`: `[{itemInId, itemOutId, unlockQuestId}]` for rows where this material is on either side (so a
    trade appears under both of its materials). **Direction (confirmed):** `itemInId` is the item the player
    RECEIVES and `itemOutId` the item the player HANDS IN. `unlockQuestId` is the quest the player clears to unlock the
    trade; it refers to `quests.json` (kind `quest`) or is null. How this was confirmed: the data pattern (in 119 of
    128 trades the `item_in_id` side has no source outside the Wyporium, the same column in all 119, 0 exceptions; the
    id ranges of the two columns never overlap; the 9 trades where both sides have other sources use the same
    column) plus Hex's in-game check of trade 1 (hand in G.Jaggi Claw, receive Arzuros Shell). It is applied to all
    128 trades. **Quantities are not in the data**; nothing may claim 1:1 or any amount. A material is a Wyporium
    source only for the trades where it is `itemInId`.
- An item can still have no link at all (the converter reports how many).
- An item that is a recipe material is only in `materials.json`, never also in `items.json`.

## quests.json
Only quests referenced by `materials.sources` (reward quests, wyporium unlock quests, arena quests):
`[{id, kind, name, hub, type, stars}]`. `kind` is `quest` (from `quests`) or `arena` (from `arena_quests`).
The two kinds have **separate id spaces**: identify a record by `(kind, id)`. Arena records have `hub`, `type` and
`stars` null (the source has no such columns). Sorted quests first, then arena, each by id.

## items.json
Items referenced by `materials.sources` that are not themselves recipe materials (combining ingredients, wyporium
counterparts, veggie offer items): `[{id, name, type, rarity}]`. Recipe materials are in `materials.json`.

## monsters.json
All monsters: `[{id, name, class, hitzones:[{part, cut, impact, shot, fire, water, ice, thunder, dragon, ko}]}]`.
Hitzone values as stored; the meaning of `ko` and of repeated parts is unverified.

## locations.json
`[{id, name}]` only for locations referenced by `materials.gathering`.
